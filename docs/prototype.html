Spec v1 · read in plain terms

Most of Dad Care is software. We can build and test it before buying a single sensor.

The spec has two sides: a four-button phone screen for Dad and a calm dashboard for Phil. Everything they see is a web app. Hardware only feeds it signals: where Dad is, whether he fell, whether the house has power. If we fake those signals with a simulator that speaks the same event format, the whole product can be built and trusted first, and each device later becomes a drop-in replacement.

Roadmap coverage without hardware
Build for real now

Web only, no devices

  • Dad's four-button PWA with press-and-hold, tremor guard and spoken confirmations
  • Check-in faces and the follow-up question
  • Medication reminders: speak at dose time, remind at 30 min, alert Phil at 60 min
  • Voice notes with transcripts, replies read aloud
  • Help me walk beat (audio + vibration)
  • Phil's dashboard: day colour, timeline, alerts, people
  • Emergency ladder: SMS + voice calls to Jos contacts, 3-minute rollover, responder link
  • Offline queue, low-battery and "phone offline" alerts
  • Health: adherence and mood trends
Build now, simulate the input

Real logic, fake signals

  • House map setup: room photos, tagged spots, drag-and-drop layout
  • Avatar on the map with pose and mood
  • State engine: chair, napping, asleep, bathroom, out, not sure
  • Alert rules: bathroom too long, no movement by late morning
  • Fall alert pipeline (watch fall → urgent ladder)
  • "House offline since 2:14 pm" and the daily self-test
  • Learned routine, seeded with example days
Needs the hardware

Wait for devices

  • ESP32 + mmWave sensors per room, chair and bed calibration
  • Galaxy Watch fall detection, heart rate, BLE beacon
  • Android helper: background motion, battery, launcher mode
  • Bluetooth BP cuff
  • UPS and SIM-backup router at the house
  • Tremor test uses the phone's motion sensor (works on the real S22, not in a desktop browser)
Build order

Step by step, each step shippable

  1. Foundation: Next.js app + Supabase

    One Next.js project with two roles (care receiver, caregiver). Create the spec's tables: household, person, device, event, state, alert, routine. Supabase Realtime pushes new events to Phil's screen.

  2. Dad's screen as a PWA

    The four buttons from this prototype, installable to the S22 home screen, pinned large in Samsung Easy Mode. Web Push for dose reminders. Events queue in IndexedDB when data is weak.

  3. Phil's dashboard

    Home, Today, Health and People screens reading live from the event table. The day colour and status line come from one function that turns events into Dad's state.

  4. Alert engine and emergency ladder

    Server rules for urgent, attention and info. Termii or Africa's Talking for SMS and voice calls with "press 1". Test with Phil's, Mom's and Jay's own phones in sandbox mode.

  5. Device simulator as a real service

    The simulator on the left becomes a small script that publishes to the MQTT broker on the same topics the ESP32 boards will use. The backend cannot tell it apart from real sensors.

  6. House map setup flow

    Walk-through capture on a phone: photo per room, say its name, tap the chair, bed, toilet and door. Phil arranges room cards on the web. Turn photos into illustrated tiles.

  7. Swap in hardware, one device at a time

    Start with one ESP32 in the sitting room aimed at the chair. Keep the simulator running for the other rooms until each real sensor is paired by QR code.
